# Home-lean investigation — which features drive it

Generated by `scripts/home_lean_feature_analysis.py` (report-only), 2026-08-07.
n=222 rated+resolved games with a logged `x_scaled_features` vector (all of them —
this field has been captured on every prediction). Follow-up to
`scripts/clv_and_skew_diagnostics.py`'s finding that the model runs +1.37pp more
home-leaning than the market (p=0.027).

## 1. Ruled out: the model's home-field baseline is not stale

```
LR intercept alone (all diffs=0) implies : 0.5298
actual 2026 home win rate (this sample)  : 0.5315
-> NOT stale — matches closely, gap = -0.17pp
```

A plausible hypothesis going in was that the LR's intercept — trained on 2021-2025 data
— encodes an outdated home-field-advantage assumption that no longer matches 2026's
actual home win rate. **It doesn't.** The intercept-implied baseline (52.98%) tracks the
actual 2026 rate (53.15%) to within 0.17pp. This is not the mechanism.

## 2. The real mechanism: the model reacts to certain features far more than the market does

For each feature, correlation with the model's home probability vs. correlation with
the market's (de-vigged) home probability:

```
feature                      corr w/ MODEL corr w/ MARKET   excess
diff_sp_siera                      -0.6228        -0.1502  +0.4726
diff_sp_xfip                       -0.6135        -0.1669  +0.4466
diff_roll10_runs_scored            +0.3953        -0.0441  +0.3512
diff_roll30_k_per_pa               -0.4515        -0.1472  +0.3043
diff_roll10_win_pct                +0.4820        +0.1830  +0.2989
diff_roll30_opp_whip               -0.5997        -0.3320  +0.2677
diff_roll30_iso                    +0.4583        +0.2054  +0.2529
```

Two clusters stand out:

**SP quality proxies** (`diff_sp_siera`, `diff_sp_xfip`): the model's probability moves
with these ~4x more than the market's does (0.61-0.62 vs 0.15-0.17). The market
clearly prices starting pitcher quality too — just far more conservatively than this
model does.

**Short 10-game rolling recent-form** (`diff_roll10_runs_scored`, `diff_roll10_win_pct`):
the model leans on these heavily (0.40, 0.48) while the market is close to indifferent
to them (-0.04, 0.18). A 10-game window is noisy by construction (recent hot/cold
streaks regress hard), and an efficient market has learned to discount it — the model
apparently hasn't learned to the same degree.

This is the textbook signature of a model overfit to noisy, short-window inputs
relative to what the market — an aggregate of far more information and money — has
learned actually holds up.

## 3. Where the average +1.37pp comes from: mostly weighting, some real composition

```
intercept                : +0.1195
sum(mean_feature * coef) : +0.0562   (the average tilt these 222 games happen to have)

Top contributors:
  diff_roll30_opp_whip         +0.0230
  diff_sp_xfip                 +0.0206
  diff_bullpen_era             +0.0094
  diff_roll30_iso              +0.0084

mean LR-only prob (recomputed from X) : 0.5425
mean LIVE ensemble prob (blended)     : 0.5483
ensemble adds beyond LR alone          : +0.58pp
```

Two things worth separating:

- **A modest, sample-specific compositional tilt** (+0.056 logit, ≈+1.4pp): in this
  particular 222-game window, home teams happen to have slightly better underlying
  `diff_roll30_opp_whip` and `diff_sp_xfip` values. This is not evidence of a bug — it
  could simply be true of this stretch of the 2026 schedule — but combined with the
  model over-weighting those exact features relative to the market (§2), it turns a
  small real tilt into a larger-than-warranted probability shift. **This part may not
  replicate on a different slice of games** — treat it as sample-specific, not a fixed
  property of the model.
- **The ensemble (GB + XGB + the 4% blend) adds only +0.58pp beyond what LR alone would
  produce.** This is an LR-feature-weighting effect learned at training time, not an
  artifact of the tree models or the recalibration blend.

## 4. Checked and set aside: feature redundancy is not the cause

```
corr(diff_sp_xfip, diff_sp_siera) = +0.9881   (near-duplicate signal)
LR coefficients: xfip=-0.1257  siera=-0.0114  era=+0.0087
```

xFIP and SIERA are 98.8% correlated — both estimate defense-independent pitcher quality
by different formulas, so this isn't surprising, but it initially looked like a
plausible smoking gun (double-counting one signal through two channels). It isn't: the
LR already puts nearly all its weight on `xfip` and almost none on `siera` despite the
near-collinearity, so the two aren't compounding each other's effect. **Worth
simplifying for interpretability and to free up model capacity, but not what's driving
the home lean.**

## What this means, and why no code changed here

The home lean isn't a home/away bug in the traditional sense (no home-specific term
exists anywhere in the feature set — every feature is a symmetric `home_X - away_X`
diff). It's a **general overfitting-to-noisy-features problem** (SP defense-independent
metrics and 10-game rolling form get more weight than the market's efficient pricing
suggests they deserve) that happens to net out home-leaning on this particular sample
because of which teams' underlying numbers currently look good.

This means the fix, if one is pursued, is **not** a home-side correction hack (like
subtracting a constant from home predictions) — that would treat the symptom on this
one sample and likely stop working once the compositional tilt shifts. The right lever
is feature-level: shrink or discount `diff_roll10_*` (noisier, shorter window than the
`roll30_*` features that survived earlier feature selection for the same reason —
see `FEATURE_COLS`'s own comments) and re-examine how much weight `diff_sp_xfip`/
`diff_sp_siera` should carry relative to what the market credits them.

**Not implemented here, deliberately.** That's a retraining + validation cycle (new
CV holdout, leak checks, comparison against the current `b9133b95d2ec` artifact before
any deploy) — a materially bigger and riskier undertaking than the two fixes already
shipped this session, and this investigation was scoped as "chase it," not "fix it."
Recommend scoping a dedicated retrain-and-validate task next, informed by this
analysis, rather than hand-patching feature weights ad hoc.
